Project 04 - README

Supervisor
Management App

A Django web application that manages exam supervision duties for schools, colleges, and universities. Administrators broadcast supervision requests to staff or outsiders, who accept or decline them - simplifying a long manual process.

Python 3.12 Django 4.2 Bootstrap 5.3 SQLite Custom Auth

01 Features

Admin Panel

  • Broadcast supervision requests to Teaching Staff, Outsiders, or both.
  • Configure Blocks / Floors / Rooms for the institution.
  • Configure School (Standards, Sections, Subjects) or University (Courses & Semesters).
  • Manage users - approve, deactivate, or directly create accounts.
  • View all requests with filters by status and target group.
  • Track who accepted each request and how many declined.

User Panel

  • View all open supervision requests broadcast to them.
  • Accept a request - first to accept claims it (race-condition safe).
  • Decline a request with a reason (disappears from their list).
  • Track accepted and declined history.
  • Edit personal profile.

System-wide

  • Two user types: Teaching Staff and Outsider.
  • Self-registration requires admin approval before login.
  • Admin-created users are immediately approved.
  • Institution configuration is persistent - set once, used everywhere.

03 Installation & Setup

Prerequisites: Python 3.10+ and pip.

# 1. Clone / download the project
cd path/to/Supervisor

# 2. (Optional) Create a virtual environment
python -m venv venv
venv\Scripts\activate        # Windows
# source venv/bin/activate   # macOS / Linux

# 3. Install dependencies
pip install -r requirements.txt

# 4. Apply database migrations
python manage.py migrate

# 5. Create the default admin account
python create_admin.py

Running the Application

python manage.py runserver
# Open http://127.0.0.1:8000

# Default admin login
# Username: admin
# Password: admin123

04 Walkthrough

A complete workflow - from admin setup to a user accepting a request.

Step 01
Login Page

The entry point for all users. Unapproved self-registered users are blocked here until the admin approves their account. Admins route to the Admin Dashboard; staff and outsiders to their personal dashboard.

Step 02
Registration

New supervisors (Teaching Staff or Outsiders) self-register. Their account stays pending until the admin approves it.

  • Account Type - Teaching Staff or Outsider
  • Name, Username, Email, Phone
  • Department (for Teaching Staff) & Institution
Step 03
Admin - Dashboard

An overview of all supervision activity: total requests, open requests, accepted requests, registered supervisors, and pending user approvals - plus quick actions to broadcast, configure, and manage.

Step 04
Institution Configuration

Configure the institution before creating requests. Choose School (Standards, Sections, Subjects) or University (degree programs), and set up Blocks, Floors, and Rooms as removable tags.

Step 05
Broadcast a Request

Broadcast a supervision request with exam date/time, location (Block / Floor / Room), class or course info, subject, and notes. The request goes to all eligible users - the first to accept becomes the supervisor.

Step 06
All Requests

View and filter every supervision request ever broadcast - by status (Open / Accepted) and target group. Columns show location, class info, subject, status, who accepted, and number of declines.

Step 07
Request Detail (Admin)

A detailed view of a single request - full location, class/course info, which group received the broadcast, who accepted it with contact details, number of declines, and a delete option.

Step 08
Manage Users

View all registered Teaching Staff and Outsiders. Approve pending accounts, deactivate users, or view full profiles and request history. Status badges: Approved, Pending, Deactivated.

Step 09
Create User

Admins can directly create accounts without waiting for self-registration. Pick account type, fill in details, set a password - the account is immediately active and approved.

Step 10
User - Dashboard

When a Teaching Staff or Outsider logs in, they see available requests, requests they've accepted, and requests they've declined. A yellow alert banner appears when open requests await action.

Step 11
Available Requests

The full list of supervision requests, organised into three tabs: Available (open and acceptable), Accepted by Me, and Declined. Each row shows exam date, time, location, class/course info, and subject.

Step 12
Accept or Decline

Clicking View shows the full detail page with action buttons. Accept locks the request instantly so no one else can claim it. Decline opens a modal asking for an optional reason - the request leaves your list but stays open for others.

Step 13
User - Profile

Users update their personal information any time - name, email, phone, department, institution, and address. The profile card shows current account status and user type badge.
