Project 01 - README

Customer Support
Ticket Intelligence

An AI system that automatically summarizes customer complaints and predicts their category and priority using NLP and machine learning. Trained on a 10,000-ticket synthetic dataset with TF-IDF features, comparing Logistic Regression and SVM.

NLP TF-IDF Logistic Regression SVM scikit-learn NLTK

01 Understanding the Problem

The goal is to develop an AI system that automatically processes complaint text and performs three key tasks:

  • 01
    Categorization
    Identify the type of issue (e.g. microphone issue, speaker issue, etc.)
  • 02
    Priority Assignment
    Determine the urgency level of the complaint - High, Medium, or Low.
  • 03
    Summarization
    Generate a short, clear summary so support agents can quickly understand the problem.

02 Approach

An end-to-end AI pipeline that takes raw textual input and applies NLP and machine learning to predict the complaint category, assign priority, and generate a concise summary.

2.1 - Data Collection & Understanding

A labeled 10,000-ticket synthetic dataset was used, containing ticket ID, customer name, categories, complaint subjects, descriptions, status, and priority levels. Analyzed for text length, class distribution, and data quality before preprocessing.

Categories

Motherboard Issue Screen Issue Camera Issue Button Issue Battery Issue Microphone Issue Speaker Issue

2.2 - Text Preprocessing

Raw complaint text was cleaned and normalized to remove noise:

  • Converting text to lowercase.
  • Removing URLs, numbers, and special characters using regular expressions.
  • Removing stopwords using NLTK.

2.3 - Feature Extraction

The cleaned text was converted into numerical features using TF-IDF (Term Frequency–Inverse Document Frequency). Both unigrams and bigrams were considered, and the most informative features selected - enabling the models to effectively learn patterns from text data.

2.4 - Model Training

Supervised models were trained on the TF-IDF features to predict complaint category and priority:

  • Logistic Regression (final model) - models class-membership probability via a logistic/softmax function, learning a linear decision boundary.
  • Support Vector Machine (SVM) - separates classes by finding an optimal hyperplane that maximizes the margin between classes.

2.5 - Complaint Summarization

Applied only during prediction. When a user submits a new complaint, an extractive summarization technique based on TF-IDF sentence scoring generates a short, meaningful summary.

2.6 - Prediction & Confidence Estimation

The complaint is preprocessed and transformed using the saved TF-IDF vectorizer. The trained model predicts category and priority, with confidence scores from probabilistic outputs (predict_proba) or calibrated probabilities for SVM. Final output: complaint summary, predicted category, predicted priority.

03 Model Performance

Standard classification metrics were used: Accuracy, Precision, Recall, F1-score, and Confusion Matrix - evaluated for both category and priority prediction.

Logistic Regression (Final Model)

The system achieved 1.00 (100%) accuracy for category classification due to clean, well-defined labels, while priority prediction achieved 0.74 (74%) accuracy due to the subjective, context-dependent nature of urgency levels.

04 Limitations & Solutions

Limitations

  1. TF-IDF features don't understand word context.
  2. Keyword-based patterns may reduce accuracy for ambiguous complaints.
  3. Priority prediction is less accurate due to subjective urgency.
  4. Synthetic training data may not reflect real-world variation.
  5. Extractive summaries may contain grammatical errors.
  6. 100% category accuracy may indicate overfitting to clean labels.

Solutions

  1. Transformer-based models for semantic understanding.
  2. Train on real-world complaint data for generalization.
  3. Hybrid ML + rule-based logic for priority.
  4. Neural summarization for fluent, grammatical summaries.
  5. Regular validation with unseen, noisy data.
  6. Cross-validation & regularization to reduce overfitting.

05 Future Improvements

  1. Integrate context-aware deep learning models to better understand complaint semantics.
  2. Train on real-world customer support data to improve robustness.
  3. Implement advanced neural summarization for grammatically correct summaries.
  4. Enhance priority prediction by combining ML with rule-based urgency detection.
  5. Deploy the system as a real-time API for customer support platforms.
  6. Continuously retrain with new incoming complaints to reduce overfitting.

06 How to Use

Run the prediction system to get the complaint summary, category, and priority.

Step 1 - Open the prediction file

Open predict_logistic_regression.py or predict_svm.py in your editor.

Step 2 - Enter complaint details

if __name__ == "__main__":
    subject = "Microphone is not working"
    description = "I am experiencing an issue where my voice is not being captured properly during calls or recordings."

Step 3 - Run the script

python predict_logistic_regression.py
# or, for SVM:
python predict_svm.py

Step 4 - View the output

Summary: Experiencing issue phone voice captured properly during calls
Category: Microphone Issue | Confidence: 0.82
Priority: Low | Confidence: 0.46

Step 5 - Try different complaints

Change the subject and description values to simulate different issues - screen, camera, battery, or audio problems.
